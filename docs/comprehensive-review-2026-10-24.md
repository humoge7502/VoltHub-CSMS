## 0. Executive summary

VoltHub CSMS is already in the top tier of open-source charging management systems for **engineering verifiability**: race tests in CI against two real database engines, drift-gated OpenAPI, an outbox relay with effectively-once semantics, a falsifiable control loop with published negative results (E3), and an honest "limits" section. Almost nothing in this class (SteVe, CitrineOS, EVerest-based stacks) has this receipt discipline.

That makes the gaps below more valuable than usual to fix, because the project's brand is _claims with receipts_ — and five findings currently contradict documented claims:

1. **OCPP gate open on public demos** — secretless charge points authenticate with no credentials and secrets are predictable (`dev-<identity>`), while `share-demo.sh` publishes the stack to the internet. Anyone can impersonate a charger and fabricate billing input.
2. **`meterStart` is ignored** — any charger with a non-zero meter register at plug-in is overbilled by the register offset.
3. **Wallet settle has a double-credit race** under the Oracle store (the exactly-once property W5 is only tested sequentially).
4. **The unsigned `POST /me/wallet/topup` still exists** — ADR-0016's "no crediting without a signature" story is contradicted by a live, bearer-token crediting path.
5. **The control plane has no operator station-scope checks** — an operator scoped to station A can actuate chargers at station B.

Full catalog in §2 (38 items, each with severity/priority/effort/dependencies/timeline). Strategy in §1, enhancements §3, advanced features §4, additions §5, test strategy §6, skills/compliance/roadmap in §7.

### 1.3 Strategic differentiation moves (with measurable targets)

- **D1 — "The provable CSMS."** Double down on receipts: publish a public benchmark dashboard from `bench/` results; add property-based and chaos suites (§6). Target: every README claim links to a CI artifact. Nobody else does this.
- **D2 — OCPP 2.0.1 + ISO 15118 Plug & Charge.** The single highest-value moat in OSS charging right now (only CitrineOS partially covers it). Target: `TransactionEvent` + device model + security events within one quarter (A-1).
- **D3 — OCPI 2.2.1 roaming module.** Turns VoltHub into a real market participant (CPO/eMSP). No credible OSS implementation exists (A-2).
- **D4 — Digital-twin replay as a product.** The twin already reproduces scenarios from seeds; expose "replay any historical day as a what-if" in the console (A-4). Measurable: plan-vs-actual kWh honesty gap = 0 across replayed days.
- **D5 — Grid-services-ready control loop.** Extend acceptance-envelope scheduling with day-ahead/real-time price feeds and demand-response events. Measurable: cost-unit improvement over static cap beyond the proven −46.7, with shortfall < 3% (already at 2.36%).
- **D6 — Signed-metering integrity story.** Extend the EIP-191 rail to signed meter values (Eichrecht-style hash chains) — rare even commercially (A-6).
- **D7 — Multi-tenant SaaS mode.** ADR-0009 deferred it; the store port makes it tractable (tenant_id + row-level scope). Unlocks hosting for small CPOs.
- **D8 — Developer experience as adoption funnel.** One-command demo exists; add one-command _contributor_ path (devcontainer, seed variants, OpenAPI playground token) and a driver PWA demo (N-5).
